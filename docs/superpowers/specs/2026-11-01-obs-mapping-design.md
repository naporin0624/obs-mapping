# obs-mapping 設計書

日付: 2026-11-01

## 目的と背景

OBS だけでプロジェクションマッピングをしたい。

OBS 標準のレイアウト編集には次の不満がある。

- grid snap がない
- ソースの x, y, width, height を数値で手早く設定できない
- 整列機能が弱い

さらに、映像を壁の形に合わせて歪める機能もない。

想定する場面は二つある。

1. **自分で壁に映す**: プロジェクターを壁に向け、壁の面ごとに別の映像を割り当て、四隅を合わせる。
2. **VJ 現場**: mapping 情報が JSON で渡され、それを読み込むだけで配置と変形を再現する。逆に、自分で組んだ mapping を JSON で書き出して持ち込んだり、人に渡したりする。

JSON はおまけの保存形式ではなく、このプラグインの中心に置く。GUI での操作と JSON の編集は、同じ一つのデータを書き換える。JSON 形式はこのプロジェクトで独自に定義する（既存ツールの形式に合わせる必要はない）。

## ゴール

- OBS に「マッピング」用のソースを追加する。その中に複数の**面（surface）**を持ち、面ごとに別の OBS ソースを割り当てられる。
- 各面は四隅（コーナーピン）で形を決める。割り当てた映像は射影変換で正しい遠近感のまま貼り付ける。
- OBS 内のドックに表示する専用の編集 UI で、面の角をドラッグして合わせられる。
- 編集 UI には次の機能を持たせる。
  - grid snap
  - 他の面の角や辺への snap
  - 数値入力（点の x, y、面の x, y, width, height）
  - 整列（揃える、等間隔に並べる）
  - 矢印キーでの微調整
- 編集中は、プロジェクター出力にもハンドルやグリッドを重ねて表示でき、壁を見ながら合わせられる。
- マッピング全体を JSON ファイルとして書き出し、読み込みできる。

## ゴールではないもの（今回はやらない）

- 格子状の点で細かく曲げる mesh 変形（柱や曲面向け）。ただし、将来追加できるよう、データ形式には余地を残す。
- OBS の通常のシーン編集（マッピングを使わない場面）での snap や整列の改善。不満の解決はマッピング内に限る。
- OBS 標準のプレビュー画面へのマウス操作の割り込み。
- 複数プロジェクターのエッジブレンディング。
- Resolume や MadMapper など他ツールの形式の読み込み。

## やってはいけないこと（動いても失敗とみなす）

- OBS の内部実装に依存する手段（非公開 API、Qt ウィジェットの横取りなど）を使い、OBS のアップデートで壊れること。
- 射影変換が不正確で、四角形の対角線に沿った継ぎ目や歪みがプロジェクション上で見えること。四角形を二つの三角形に分けて affine で描くと、この継ぎ目が出るので不可。
- 編集用のハンドルやグリッドが、編集モードでないときに出力に映り込むこと。
- OBS の再起動や、シーンコレクションの切り替えでマッピングが消えること。

## 決まっていること

### 全体構成

- **プラグイン本体（C/C++）**: obs-plugintemplate をベースに CMake でビルドする。変形の描画は GPU のシェーダーで行う。
- **編集 UI（TypeScript）**: OBS のカスタムブラウザドックに表示する。
- **通信**: obs-websocket の vendor API（プラグインが独自のリクエストやイベントを登録する仕組み）を使う。自前のサーバーは立てない。
- **出力**: マッピング用のソースをシーンに置き、OBS 標準のプロジェクター機能でプロジェクターにフルスクリーン出力する。

### マッピング用ソース

- 新しいソース種別として追加する。
- 自身の出力解像度（幅、高さ）を設定として持つ。
- 中に面のリストを持ち、リストの順番が重なり順になる（後ろの面ほど手前）。
- 各面は次の情報を持つ。
  - ID
  - 名前
  - 割り当てる OBS ソース（ソース名で参照）
  - 元映像の切り出し範囲
  - 四隅の座標（マッピング用ソースの座標系、px）
  - 表示・非表示
- 割り当てたソースが存在しない場合、その面は何も描かずに残す。ソースが後から作られたら、そのまま表示される。
- 状態はソースの設定として保存し、OBS のシーンコレクションと一緒に永続化する。
- 「編集オーバーレイを表示」という切り替えを持つ。オンのとき、面の輪郭、角のハンドル、選択状態、グリッドをこのソースの出力に描く。オフのときは何も描かない。

### 面の変形

- 四隅の点で決まる四角形に、元映像の切り出し範囲を射影変換（ホモグラフィ）で貼り付ける。
- データ上は面に種別（例: `"type": "quad"`）を持たせる。これは将来、格子状の mesh を追加するための余地。

### JSON

- マッピング全体を一つの JSON で表す。
- 形式のバージョン番号を含める。
- 中身はキャンバス（出力解像度）、グリッド設定、面のリスト。
- 編集 UI から、ファイルとして書き出し・読み込みができる。
- 読み込み時は形式を検証し、不正なら理由を表示して、既存のマッピングを壊さない。

### 編集 UI

- 対象にするマッピング用ソースを選ぶ（シーン内に複数あってもよい）。
- マッピング用ソースの出力映像を表示する。0.1 秒程度の遅れやカクつきは許容する。正確な確認はプロジェクター出力で行う前提。
- 映像の上に面の輪郭と角のハンドルを重ね、ドラッグで動かす。
- 操作一覧:
  - **grid snap**: 指定した間隔のグリッドに吸着する。間隔は変更できる。修飾キーを押している間は無効になる。
  - **他の面への snap**: 他の面の角や辺に吸着する。
  - **数値入力**: 選んだ角の x, y を入力する。面の x, y, width, height を入力した場合は、面を長方形に戻してから配置する。
  - **整列**: 複数の面を選び、左・右・上・下・中央に揃える。等間隔に並べる。
  - **矢印キー**: 1px ずつ移動する。Shift を押しながらだと 10px ずつ。
  - 面の追加、削除、複製、並べ替え（重なり順）、割り当てソースの変更、名前の変更。
  - 編集オーバーレイ表示のオン・オフ。
  - JSON の書き出しと読み込み。

### 編集オーバーレイの映り方

- オーバーレイはマッピング用ソースの映像そのものに描く。そのため、オンの間は、そのソースが映っているすべての場所（プロジェクター、プログラム出力、配信、録画）に出る。
- これは許容する。調整はリハーサルや仕込みの時間に行い、本番中はオーバーレイをオフにして触らない運用だから。

## 対応環境

- 最初の実装は macOS だけ。開発者の手元は macOS で、OBS 33.0.0 が入っている。
- 将来は Windows にも対応したい。そのため、OS 固有の API には依存しない。グラフィックスは libobs の抽象化（gs_* と .effect シェーダー）だけを使う。

## 次の段階: 一式配布（今回の実装には含めない）

最終的には、プラグイン、編集 UI、シーンコレクション、映像素材を一式まとめて人に渡したい。これはプラグインが動いてから、別の設計として詰める。現時点で決まっていることは次のとおり。

- 署名はしない（Apple Developer Program は使わない）。受け取った人には、macOS の「システム設定 → プライバシーとセキュリティ → このまま開く」で、インストーラーを一度だけ許可してもらう。インストーラーは、残りのファイルの quarantine 属性を外す。
- シーンコレクションは素材を絶対パスで持つので、書き出し時に素材を集め、インストール時に相手の PC のパスへ書き換える仕組みが要る。
- 編集ドックを自動で登録する方法（OBS の設定ファイルを書き換えるか、プラグイン自身がドックを持つか）は未定。
- 今回の実装では、そのための下準備として、編集 UI のビルド結果をプラグインの中に同梱し、置き場所を固定する。

## 設計者（Claude）の判断で決めたこと

- 変形は「マッピング用ソース」が一括で描く方式にした。ソースごとにフィルターをかける方式も考えたが、全体を一つの JSON で管理しやすく、重なり順もまとめて扱えるので、こちらを選んだ。
- 編集 UI はネイティブ（Qt）ではなくブラウザにした。整列や数値入力の UI を早く作れること、通信を obs-websocket に任せられること、映像の遅れを許容できることが理由。
- 他の面への snap、矢印キーでの微調整、編集オーバーレイのプロジェクター表示は、会話の中で私が提案した機能。
- **元映像の切り出し範囲**: 最初のバージョンでは、編集 UI での数値入力と JSON での指定だけに対応する。初期値は映像全体。映像を見ながらドラッグで範囲を選ぶ機能は後回しにする。
- **JSON の解像度がマッピング用ソースと違うとき**: 読み込み時に違いを表示し、「点を比率で伸縮して合わせる」か「JSON の解像度で上書きする」かを利用者が選ぶ。座標は px で保存する。
- **割り当てたソースの再生**: プラグインが、割り当てたソースを表示中・アクティブとして扱う。これにより、どのシーンにも置かれていない動画やブラウザソースも再生される。同じソースを複数の面に割り当てた場合は、一つの再生を共有する。
- **音声**: マッピング用ソースは音声を出さない。音声は OBS 側で別に管理する前提。

## 実装者に任せること

- 射影変換シェーダーの具体的な実装方法（ピクセルシェーダーで逆ホモグラフィを計算するなど）。ただし、上の「継ぎ目が出ない」条件は必ず満たすこと。
- JSON の具体的なフィールド名とスキーマ。
- 編集 UI の配信方法（ドックに読み込ませる URL をどう用意するか）。
- 編集 UI の映像を取得する方法と頻度。
- 編集 UI とプラグイン本体の間で状態をどう同期するか（差分を送るか、全体を送るか）。ただし、正となる状態はプラグイン本体が持つ。
- UI のフレームワーク、見た目、undo/redo の有無。
- テストの方法。
