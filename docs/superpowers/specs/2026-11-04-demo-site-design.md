# デモサイト（変則的なマッピング 4 種）設計

## 目的

OBS ユーザーに「**変な面でも簡単にマッピングできる**」と思ってもらう。

`obs-mapping.napochaan.dev` にデモを置く。ルートは将来プラグインの HP にするので、デモはサブパス `/demo/` 以下に置く。訪問者の webcam 映像を、3D で再現した変わった形の物体にマッピングして見せる。

訪問者はマッピングを自分では操作しない。完成済みのマッピングを眺めながら、「OBS 上ではこの手順で作った」と分かるようにする。

`docs/demo/projection-room` のデモ（部屋の壁 2 面）とは関係のない、新しいシーンを 4 つ作る。

## ゴール

- 4 つのデモを作る。どれも今のプラグインの機能だけで再現できるものにする。
  1. **階段の蹴上げ**（`/demo/stairs`）: 四隅の再配置だけで作るマッピング。下から見上げた階段の、蹴上げ（各段の垂直面）1 段ごとに面を 1 つ置く。各面の `crop` で webcam 映像の横帯を受け持たせ、階段全体で 1 枚の映像に見えるようにする。
  2. **六角形タイルの壁**（`/demo/hexagon`）: 多角形 mask が必要なマッピング。ハニカム状のパネル 1 枚ごとに面を 1 つ置き、六角形の `polygon` mask で切り抜く。`crop` で 1 枚の webcam 映像をタイルに分けて割り当てる。
  3. **ドラムセットの打面**（`/demo/drums`）: 円 mask が必要なマッピング。斜めを向いた太鼓の打面ごとに面を 1 つ置き、`ellipse` mask で切り抜く。打面が斜めなので、四隅のワープによって円が楕円に見える。
  4. **積み重ねた立方体**（`/demo/cubes`）: 古典的なプロジェクションマッピング。大中小の立方体を、上の立方体が下の立方体の天面の奥の角に載るように積み、斜め上のプロジェクターへ縦の辺を向ける。各立方体の左右の側面と天面に面を 1 つずつ置く（上に立方体が載る天面は、見えている L 字を 2 本の帯に分ける）。どの面も投影先で重ならないので、レイヤーの順は結果に影響しない。`crop` は面ごとに映像の中央をその面の縦横比で切り出す。3 つの面には、外周と穴の輪郭を 1 本の点列にした `polygon` mask（even-odd）で穴を抜き、穴には光が当たらない。
- `/demo/` に 4 つのデモへの入口を並べた一覧ページを置く。各デモは個別のページにし、URL で共有できるようにする。
- 各デモのページは**投影室のビューア**にする（`docs/demo/projection-room.html` が手本）。3D の舞台が主な領域を占め、操作と説明は横のパネルにまとめる。スクロールで手順が進む作りにはしない。
- 舞台は訪問者が自由に見回せる（ドラッグで回り込み、ホイールで寄る、右ドラッグで平行移動、キーボード操作あり、視点のリセットあり）。
- 入力は「サンプル」と「OBS 仮想カメラ」から選ぶ。最初はコードで生成したサンプル映像。OBS 仮想カメラを選んだときに初めてカメラを求める。カメラの許可を拒否された場合やカメラがない場合は、サンプル映像に戻して理由を案内する。
- 各デモの `mapping.json` をダウンロードできるようにする。プラグインのドックでそのまま Import できる形式（mapping JSON v2、キャンバス 1920×1080）にする。

## やらないこと

- 訪問者がハンドルを動かしてマッピングを編集する機能。
- 格子状の mesh 変形。プラグインはまだ quad しか扱えないため。
- ルート（`/`）のプラグイン HP。
- プラグイン本体（`core/` `src/` `ui/`）の変更。

## やってはいけないこと

- **今のプラグインでできないことを、できるように見せてはいけない。** 3D の見た目は、ダウンロードできる `mapping.json` の内容（四隅・crop・mask）だけから作る。JSON と見た目が別々に作られて食い違う作りは避ける。
- **曲面を細い quad で近似するような裏技的なマッピングを、デモの題材にしてはいけない。** どのデモも「面 1 つ = 平らな物体の面 1 つ」で素直に成り立つものにする。
- **webcam の映像をブラウザの外に送ってはいけない。** 処理はすべてページ内で完結させる。
- **カメラの許可ダイアログを入口に置いてはいけない。** ページを開いた時点ではカメラを求めない。
- **会場から受け取った資料や、それを元にした数値を使ってはいけない。** シーンと座標はすべて新しく作る。

## 決まっていること

### 置き場所と技術

- このリポジトリの `site/` に置く。Astro と three.js で作る。
- パッケージ管理は pnpm。lint / fmt / typecheck はリポジトリの方針（oxlint・oxfmt・`@typescript/native-preview`）に合わせる。husky のコミット時チェックに `site/` も含める。
- テストは vitest（できれば browser mode）。座標の計算、JSON の生成など、純粋な関数は TDD で作る。
- Cloudflare Workers の静的アセットとしてデプロイする。`obs-mapping.napochaan.dev` を割り当てる。
  - まずは `cf` CLI（`cloudflare.config.ts`）を使い、手元からコマンドでデプロイする。GitHub Actions でのデプロイと、PR ごとのプレビュー URL は今回は作らない。
- `site/` の変更でプラグインのリリースやビルドが動かないようにする（私の判断）。
  - release-please の対象から `site/` を外す。
  - プラグインのビルド CI は、`site/` だけを変えた PR では動かさない。
  - これに必要な `release-please-config.json` と workflow の `paths` の変更は、今回の範囲に含める。

### 言語

- 日本語と英語の 2 言語にする（ドックと同じ）。最初から i18n のルーティングを入れる。
- URL の分け方（`/demo/` と `/en/demo/` のように分けるか、など）と、初めて開いたときにどちらの言語を出すかは、作る人に任せる。
- 手順の文章に出てくるドックの操作名（「形を編集」/ "Edit shape" など）は、`ui/src/i18n` の各言語の文言と一致させる。

### 見た目

- 見た目はドック UI と同じ Cannelloni（デザインシステム）に合わせる。色・文字・余白の token を揃える。
- 色は WCAG 2.1 AA を満たす。
- 幅 900px 以上では、舞台の右に約 360px のパネルを置く。パネルは単独でスクロールし、舞台の高さは「100dvh − ヘッダー」にする。スマートフォンでは、上に舞台（約 56dvh）、その下にパネルを通常の流れで置く。390px 幅で横スクロールを出さない。
- パネルの順番: タイトルと一文の説明 → 入力（ラジオ、カメラの選択、状態の案内、サンプルの一時停止）→ 手順 → 表示（「投影範囲を表示」、視点のリセット）→ 「OBS でつなぐ」の番号付きリスト。
- 舞台には、プロジェクターの本体と、レンズから投影範囲までの線（投影範囲）を描く。線は「投影範囲を表示」チェックボックス（初期値オン）で切り替える。
- `prefers-reduced-motion` が有効な場合は、手順の切り替えでアニメーションさせず、視点の慣性も切り、サンプル映像を止めた状態から始める。

### 手順の見せ方（各デモ共通の流れ）

手順はパネルの中のネイティブなラジオボタン（fieldset）で選ぶ。初期値は「完成」。選んだ手順の状態へ約 1.2 秒で移る（視点は訪問者が決めるので動かさない）。OBS 仮想カメラが入力のあいだは、送られてくる映像がすでに完成した出力なので、手順の選択を無効にして一文で理由を示す。文章は OBS とドックで実際に行う操作の名前を使う。

1. OBS にカメラのソースを `Demo Camera` という名前で追加し、Mapping ソースを追加する。シーンでは、四角い映像がそのまま物体に当たっている。
2. ドックで面を追加し、映すソースに `Demo Camera` を選んで、四隅を物体の面に合わせる。シーンでは、面ごとに映像の角が物体の角へ移っていく。`crop` で映像を分ける様子もここで見せる。
3. （デモ 2・3・4 だけ）形を多角形 / 円にして切り抜く。シーンでは、面の外にはみ出していた部分が消える（デモ 4 では面の穴が抜ける）。
4. 完成。立体物に貼り付いた状態。`mapping.json` のダウンロードは「OBS でつなぐ」の最初の項目に置く。

### OBS 仮想カメラの入力

- 訪問者は `mapping.json` を OBS のドックで Import し、仮想カメラを開始して、このページで「OBS 仮想カメラ」を選ぶ。
- カメラの映像はプロジェクターの映像そのものとして、**ページ内の出力レンダラーを通さず**そのまま投影する。ページ内の出力レンダラーを通すのはサンプル映像だけ（OBS が出す出力の代わり）。
- 映像が 16:9 でない場合は、引き伸ばしも切り抜きもせず、黒い帯を足して 16:9 に収める（レターボックス）。そのことを状態の案内で伝える。
- カメラを開いたあとで機器の一覧を読み、名前に `OBS` を含むカメラを優先して開き直す。ほかのカメラは選択リストから選べる（許可されるまでリストは隠す）。別のカメラへの切り替えに失敗したときは、今のカメラのまま失敗だけを伝える。

### mapping.json

- 各デモの JSON はリポジトリに置き、ページの表示とダウンロードの両方で同じものを使う。
- 全面の `source` を固定名 `Demo Camera` にする（名前は私の判断）。ダウンロードボタンのそばに「OBS のカメラソースの名前を `Demo Camera` にしてから Import する」と案内する。
- テストで次の 2 つを確かめる。
  - ドックの読み込み処理（`ui/src/model/read.ts` の `readMapping`）で検証が通ること。
  - C++ 側の `parse_surface`（`core/src/mapping_json.cpp`）が課す条件も満たすこと。たとえば crop が範囲に収まること（`x + width ≤ 1`）、キャンバスの大きさが整数であること（私の判断）。計算で crop を割り振る六角形のデモでは、丸め誤差で 1 をわずかに超えないよう特に注意する。

## 作る人に任せること

- 3D の見た目を JSON から作る方法。例: JSON どおりに 2D の「OBS 出力」をレンダーターゲットに描き、仮想プロジェクターから物体へ投影する（projective texture mapping）。こうすれば JSON と見た目が自然に一致する。
- 各シーンの物体の寸法、カメラとプロジェクターの位置、段数・タイル数・太鼓の数。
- サンプル映像の柄（動くグラデーション、テストパターンなど）。歪みや切り抜きが分かりやすい柄にする。
- 表示していないページや画面外のときに描画を止める工夫。
- Cannelloni の token を Astro からどう使うか（`ui/` の Panda CSS 設定を共有するか、token だけ取り出すか）。
- 一覧ページ `/demo/` のレイアウトと、各デモのサムネイル。
- ルート `/` の扱い（HP ができるまでの仮のページにするか、`/demo/` へ転送するか）。
