# 面の Mask（円・多角形の切り抜き）設計

## 目的

会場から届く LED ビジョンのチャートには、円形のビジョンがよく含まれる。たとえば正方形の領域に円形ビジョンが内接している場合や、矩形より円のほうが大きく、円の一部が矩形からはみ出して欠けている場合がある。

今の面（Surface）は「元映像を矩形で切り出す（crop）→ 四隅をワープする」ことしかできない。そのため円の外側の四隅にも映像が描かれる。面どうしを近づけたり重ねたりすると、**円の外側が隣や下の面に被さり、そちらの映像を隠してしまう**。これを防ぎたい。

面ごとに Mask を 1 つ持たせ、Mask の外側を透明にする。そうすれば下の層が見える。

## ゴール

- 面ごとに Mask を 1 つ設定できる。種類は「なし / 円 / 多角形」の 3 つ。
- Mask は面の中の座標で決まる。四隅をワープすると、Mask も面と一緒に歪む。円は楕円や卵形になる。
- Mask の外側は完全に透明にする（OBS 出力でもドックのプレビューでも同じ）。面の矩形からはみ出した部分は自然に欠ける。
- 形はドックの上で、ドラッグと数値入力の両方で作れる。
- mapping JSON v2 に保存し、Export / Import で引き継ぐ。

## やらないこと

- 画像（PNG など）を使った Mask。
- 1 つの面で複数の形を組み合わせること（和・差・くり抜き）。
- 輪郭のぼかし（フェザー）。
- Mask の反転（内側を抜くこと）。

## やってはいけないこと

- **既存の mapping を壊したり、見た目を変えたりしてはいけない。** `mask` が無い面は、今までどおり矩形全体を描く。
- **OBS 出力の描画を目に見えて重くしてはいけない。** Mask の判定は描画中の面に対してだけ行う。フレームごとに CPU で画像を作り直すこともしない。
- **四隅ワープの操作を Mask 編集と取り違えさせてはいけない。** 四隅ハンドルと Mask ハンドルを同時に出さない。

## 決まっていること

### データモデル

- `Surface` に省略可能な `mask` を足す。無い場合は「なし」と同じ扱いにする。
  - 円: `{ "type": "ellipse", "x", "y", "width", "height" }`。外接矩形で表す。width と height が違えば楕円になる。
  - 多角形: `{ "type": "polygon", "points": [[x, y], ...] }`。頂点は 3 つ以上。
- 座標は**面の単位正方形（crop 後の 0〜1）に対する割合**で保存する。シェーダーの `s`（`warp.effect` の `PSWarp` で、四隅ワープを逆変換した後の座標）と同じ空間にする。
  - こうすると四隅ワープで Mask も一緒に歪む。面を拡大縮小すれば Mask も一緒に伸び縮みする。
  - crop を変えても、Mask は面に対する位置を保つ（元映像の上で固定されるわけではない）。
- 範囲は 0〜1 の外にはみ出してもよい（矩形からはみ出す円を表すため）。描画では面の矩形との共通部分だけが見える。
- JSON のバージョンは v2 のまま。`mask` は任意フィールドとして足す。今の C++ パーサーは知らないキーを無視するので、古いプラグインで読んでも Mask が無視されるだけで壊れない。
- UI の `readMapping`（`ui/src/model/read.ts`）と C++ の `parse_surface`（`core/src/mapping_json.cpp`）の両方で検証する。不正な `mask`（頂点が 3 つ未満、width / height が 0 以下、数値でない、未知の type）はエラーにする。
- C++ 側でも `model.hpp` の `Surface` に `mask` を足し、`serialize_mapping` で書き出す。読み込みから書き出しまでを通しても `mask` が残るようにする。古いプラグインが mapping を書き直すと `mask` は消えるが、それは許容する。

### 描画（OBS 出力）

- `warp.effect` の `inside` に Mask の被覆率を掛ける。
- 輪郭は 1 px 程度のアンチエイリアスにする。
- ブレンドは今と同じ `ONE / INVSRCALPHA`（乗算済みアルファ）のまま。被覆率はサンプル結果全体に掛ける。

### ドックのプレビュー

- `StageSurface` の切り抜きに Mask を反映する。今は `cropCls` の div を `matrix3d` で四隅に写しているので、その div（面の単位正方形の空間）に `clip-path` を掛ければワープと一緒に歪む。
- OBS 上の編集オーバーレイ（`src/overlay.cpp`）には、Mask の輪郭を四隅ワープ後の座標で描く。輪郭だけで、Mask のハンドルは描かない。形の編集モードはドックだけの状態として扱い、`setOverlay` のプロトコルは変えない。

### 操作

- 編集モードは 2 つ。
  - **通常**: 面を選ぶと四隅ハンドルが出る（今と同じ）。Mask の輪郭は細い線で見えるだけ。
  - **形の編集**: 次のどちらかで入る。Esc を押すか、編集中の面の四隅の外をクリックすると抜け、面を選んだ状態に戻る。モード中は四隅ハンドルを隠し、Mask ハンドルだけを出す。
    - 「最後のダブルクリック」: 今のダブルクリックは、グループの中へ一段ずつ入る操作（`use-stage-drag.ts` の drill）のまま残す。面が選ばれていて、それより奥が無い状態でダブルクリックしたときだけ、形の編集に入る。
    - Inspector の「形を編集」ボタン。
- **クリックの当たり判定は Mask を見る。** Mask の外（透明な部分）をクリックすると、その下に見えている面が選ばれる。ステージでの選択とドラッグの開始判定（`stage-pick.ts` / `surfaceAt`）を、面の単位正方形の中で楕円・多角形の内外を判定する方式にする。判定の塗りつぶし規則はシェーダーと同じにする。
- 円の編集: 外接矩形の上下左右の辺の中点にハンドルを出す。中心をドラッグすると移動する。
- 多角形の編集: 頂点をドラッグで動かす。辺をクリックすると頂点が増える。頂点を選んで Delete で消す（3 つ未満にはならない）。
- Inspector:
  - 「形」セグメント `[なし | 円 | 多角形]` と「形を編集」ボタンを置く。
  - 円: X / Y / W / H の数値欄。
  - 多角形: 選んでいる頂点の X / Y の数値欄。
  - 数値は**面の表示サイズ（`boundsOf(surface)` の幅・高さ、px）に換算して**表示・入力する。図面に書かれた px の数値をそのまま入れられるようにするため。X / Y は面自身の左上からの px（単位正方形の割合 × バウンディングボックスの幅・高さ）で表す。キャンバス上の絶対座標ではない。
  - 四隅が矩形でない（歪ませた）面では、この換算は近似になる。それで構わない。図面どおりの数値を入れる場面は、ほぼ矩形の面だからである。
- 種類を切り替えた直後の初期形:
  - 円: 内接円（`x=0, y=0, width=1, height=1`）。
  - 多角形: 矩形の 4 頂点。
  - 「なし」に戻すと `mask` を消す。
- Mask の変更は今の undo / redo とドックから OBS への送信の流れに乗せる。
- グループの Auto Layout は Mask を見ない。並べ方の大きさは今と同じく四隅のバウンディングボックスで決める。

### UI の規則

- 新しいコンポーネントは `src/components/<kebab-case>/index.tsx` と `styles.css.ts` に置き、colophon にも足す。
- 文言は i18n（`ja.ts` / `en.ts`）に足す。
- 色は既存の token を使い、WCAG 2.1 AA を満たす。

## 作る人に任せること

- シェーダーで多角形を判定する方法（uniform の配列で頂点を渡す、CPU で小さな Mask テクスチャを作り変更時だけ更新する、など）。OBS の effect は D3D と GLSL の両方に変換されるので、両方で動く方法を選ぶこと。頂点数に上限を設けてよい（例: 32）。その場合は UI 側でもそれ以上増やせないようにする。
- 多角形が自己交差したときの扱い（even-odd か non-zero か）。UI と OBS で同じ結果になること。
- 円のハンドルの細かい見た目と当たり判定の大きさ。
- 単位正方形の割合と px の換算をどこに置くか（`editor/` に純粋関数として置くのが今の構成に合う）。
- 編集モードを `Selection` に持たせるか、別の state にするか。

## 確認方法

- ユニットテスト（vitest / core の ctest）: JSON の読み書きと検証、割合と px の換算、多角形の頂点の追加・削除、初期形。
- OBS の実機でしか見られない項目（被覆の見た目、アンチエイリアス、重ねたときに下の面が見えること、D3D / Metal の両方での描画）は `docs/manual-checks.md` に足す。
- 円形ビジョンを含む実際の会場チャートを再現した Import 用 JSON をローカルで作り、手で確認する。
  - **会場から受け取った資料（チャート画像）と、それを再現した JSON・数値は、絶対にコミットしない。** ファイルはリポジトリの外（作業用の一時ディレクトリなど）に置く。
  - 確認したい形: 正方形に内接する円、矩形からはみ出して欠ける円、小さな内接円の 3 種類。
  - 会場の数値を使わない汎用のテスト用データ（テストの fixture など）は、コミットしてよい。
