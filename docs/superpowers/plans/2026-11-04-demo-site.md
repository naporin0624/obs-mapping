# デモサイト実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `site/` に Astro + three.js のデモサイトを作り、`/demo/` 以下に「階段の蹴上げ」「六角形タイルの壁」「ドラムセットの打面」の 3 つのマッピングデモを日英 2 言語で置く。

**Architecture:** 各デモは「3D の物体（props）」と「仮想プロジェクター」を定義した `SceneSpec` から始まる。物体の面の四隅をプロジェクターのカメラで 1920×1080 に投影して `mapping.json` を生成し、リポジトリに置く。ページでは、その JSON どおりにプラグインと同じ計算（単位正方形 → 四隅のホモグラフィ、crop、mask、even-odd）で 2D の「OBS 出力」をレンダーターゲットに描く。それを同じプロジェクターから 3D の物体へ投影する（projective texture mapping）。こうして JSON と見た目が仕組みの上で一致する。スクロールに応じて `stageFrame` が「完成形の Mapping」から途中の Mapping を作り、描画する。

**Tech Stack:** Astro（静的出力、i18n ルーティング）、three.js、TypeScript（`@typescript/native-preview` の tsgo）、vitest（node プロジェクトと browser mode プロジェクト。browser は Playwright の chromium）、oxlint / oxfmt、pnpm、Cloudflare の `cf` CLI、culori（テストだけで使う。コントラスト計算）

**Spec:** `docs/superpowers/specs/2026-11-04-demo-site-design.md`。日本語で書かれており、この計画より優先する。

## Global Constraints

- 作業ブランチは `feat/demo-site`。**commit はしない。** 各タスクの最後は `git add` だけにする（stage for review）。タスクが終わったら difit を起動してユーザーにレビューを頼む。
- pnpm を使う。`site/` は `ui/` と同じく独立したパッケージ（自前の `pnpm-lock.yaml` と `mise.toml`。node `24.15.0`、pnpm `10.21.0`）にする。
- `pnpm -C site fmt` は `oxlint` と `oxfmt --write`、`pnpm -C site lint` は `oxlint` と `oxfmt --check` を実行する。`pnpm -C site typecheck` は tsgo。`pnpm -C site test`、`pnpm -C site build` も含め、すべて通ること（lint の警告 0）。
- 知らないライブラリの API（Astro の i18n と endpoint、vitest browser mode、three.js の RenderTarget や ShaderMaterial、`cf` CLI）は、使う前に context7 か web で調べる。
- vitest で red-first の TDD を行う。WebGL・DOM・メディアが要るテストは `*.browser.test.ts` にして browser プロジェクトで走らせる。それ以外は `*.test.ts` で node プロジェクトに置く。
- `oxlint-disable` は使わない。関数は単一責任にし、コメントは必要なときだけ 3 行以内にする。
- 暗黙の副作用を作らない。カメラ・描画ループ・スクロールの購読などは `start…()` が止めるための関数を返す形にし、ページのスクリプトがつなぐ。
- UI は HTML + CSS を第一にする。リンクやボタンは素の `<a>` / `<button>` で作る（`site/` は React を使わない）。
- 色は Cannelloni の token（`ui/panda.config.ts` の値）を使い、WCAG 2.1 AA を満たす。
- プラグインと同じ判定は `ui/` のコードを相対 import して再利用する（`ui/src/model/read.ts` の `readMapping`、`ui/src/model/mapping.ts` の型、`ui/src/geometry/homography.ts`、`ui/src/geometry/mask.ts`）。`ui/` 自体は変更しない。
- mapping JSON の値（spec と既存形式どおり）: `version: 2`、`canvas: { width: 1920, height: 1080 }`、`grid: { size: 20 }`、`groups: []`、`layers` は surfaces の順の平らな配列。四隅の順は TL, TR, BR, BL。全面の `source` は `"Demo Camera"`。mask の内外判定は even-odd。
- 会場資料や、それを元にした数値は使わない。

## Review Focus

1. **カメラを拒否された、カメラがない、使用中にカメラが抜かれた。** どの場合もサンプル映像に戻り、理由を案内する。→ Task 9 に、`getUserMedia` が `NotAllowedError` / `NotFoundError` で失敗したときと、track の `ended` が起きたときのテストを置く。
2. **カメラが 16:9 でない（4:3 の webcam、縦向きのスマートフォン）。** 映像を引き伸ばさず、中央を 16:9 に切り出してから「OBS のソース」として扱う。→ Task 9 に `coverCrop` のテストを置く。
3. **ページの途中で再読み込みした、アンカーで飛んだ、素早くスクロールした。** 段階はイベントの順序ではなくスクロール位置だけから決まるべき。→ Task 6 の `scrollProgress` を、位置だけを受け取る純粋関数としてテストする。
4. **WebGL が使えない、context が失われた。** 手順の文章とダウンロードは使えたまま、3D の場所に案内を出す。→ Task 11 に、WebGL の初期化が失敗したときにフォールバック表示になる browser テストを置く。
5. **タブを隠した、ページを離れた、3D が画面外にある。** 描画ループを止め、ページを離れるときはカメラの track を止める。→ Task 11 に、`visibilitychange` で描画が止まり、`pagehide` で track の `stop()` が呼ばれるテストを置く。

### Task 2: 投影の幾何と `SceneSpec` から Mapping を作る処理

**Files:**

  type Vec3 = readonly [number, number, number];
  type Projector = { position: Vec3; target: Vec3; up: Vec3; fovY: number }; // aspect は常に 16/9

  type Face = { id: string; name: string; corners: readonly [Vec3, Vec3, Vec3, Vec3]; crop: CropRect; mask?: Mask };
  type Prop =
    | { kind: 'box'; center: Vec3; size: Vec3; rotationY: number }
    | { kind: 'hexPanel'; center: Vec3; radius: number; depth: number; normal: Vec3 }
